# YAML configuration guide

This file explains how to modify the YAML files used by the PBLT pipeline.
Run commands from the repository root with the `meta_env` environment
activated.

## Configuration files


| File                       | Purpose                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------- |
| `configs/default.yaml`     | Dataset paths, integrated frequency bands, time window, baseline, and general statistics. |
| `configs/comparisons.yaml` | Event pairs and statistical threshold used by the comparison stage.                       |
| `configs/lmm.yaml`         | Mixed-model preset and p-value correction.                                                |
| `configs/run_all.yaml`     | Stages executed by `run_all.py` and output reuse policy.                                  |

Relative paths in a YAML file are interpreted relative to that YAML file.
Use absolute Windows paths when data are stored outside the repository.

## 1. Main dataset configuration

Edit `configs/default.yaml`:

```yaml
dataset:
  tfr_root: "C:/path/to/epoched_tfr_data"
  roi_file: "C:/path/to/PBLT_ROIs.csv"

intermediate:
  output_root: "../outputs"
  bands:
    Theta: [4, 8]
    Alpha: [8, 12]
    Beta: [12, 30]
    Gamma: [30, 50]
    HFA: [50, 150]
  time_min: 0.0
  time_max: 0.8
  baseline_type: raw
  include_outside: false

statistics:
  alpha: 0.05
  correction: fdr_bh
```

Supported baseline values are `raw`, `div`, `zscore`, `log_div`, and `diff`.
The available frequency-band names are `Theta`, `Alpha`, `Beta`, `Gamma`, and
`HFA`. The current integration code uses these predefined bands.

Generate intermediate data with:

```powershell
python .\scripts\01_generate_intermediate.py `
    --config .\configs\default.yaml
```

Add `--overwrite` only when the configured output location may be replaced.

## 2. Event coding and comparisons

The event codes are:


| Code | Meaning      |
| -----: | -------------- |
|  `0` | Gain failure |
|  `1` | Loss failure |
|  `2` | Gain success |
|  `3` | Loss success |

The supported comparisons are:


| Name              | Codes      | Meaning                        |
| ------------------- | ------------ | -------------------------------- |
| `plus1_vs_minus1` | `2` vs `1` | Overall comparison, `+1 vs -1` |
| `plus1_vs_zero`   | `2` vs `0` | Gain comparison, `+1 vs 0`     |
| `minus1_vs_zero`  | `1` vs `3` | Loss comparison, `-1 vs 0`     |

These pairs are declared in `configs/comparisons.yaml`:

```yaml
events:
  comparisons:
    - name: plus1_vs_minus1
      first: 2
      second: 1
      label: "+1 vs -1"
    - name: plus1_vs_zero
      first: 2
      second: 0
      label: "+1 vs 0"
    - name: minus1_vs_zero
      first: 1
      second: 3
      label: "-1 vs 0"
```

The comparison stage validates these definitions and writes the comparison
tables:

```powershell
python .\scripts\02_run_comparisons.py `
    --config .\configs\comparisons.yaml `
    --input-output .\outputs\baseline_raw_YYYYMMDD
```

The entries now control the simple comparison barplots. Keep all three entries
to generate all simple plots by default. For example, to generate only the
overall and gain plots:

```yaml
events:
  comparisons:
    - name: plus1_vs_minus1
      first: 2
      second: 1
      label: "+1 vs -1"
    - name: plus1_vs_zero
      first: 2
      second: 0
      label: "+1 vs 0"
```

The final gain/loss category barplot still requires the gain and loss
comparisons together and is generated when either `plus1_vs_zero` or
`minus1_vs_zero` is requested.

## 3. Generate the comparison barplots

The plotting stage reads the saved pairwise comparison CSV and generates the
positive and negative regional barplots. By default, it also generates the
historical final barplot combining the gain (`+1 vs 0`) and loss (`0 vs -1`)
comparisons.

### Additional overall plot: `+1 vs -1`

The first-stage analysis separately produces the overall comparison
`+1 vs -1` and stores its regional summary here:

```text
fig/summary/minus1_vs_plus1/minus1_vs_plus1_by_band_and_region.png
```

This plot is distinct from the final gain/loss category barplot below.
It is generated by the statistical analysis stage and is not replaced by the
final barplot.

```powershell
python .\scripts\03_generate_response_plots.py `
    --config .\configs\default.yaml `
    --input-output .\outputs\baseline_raw_YYYYMMDD
```

The final plot is written to the historical location:

```text
outputs/<analysis>/
├── data/gain_loss_responses/
│   ├── pairwise_comparison_results_by_band.csv
│   └── filtered_electrode_lists/
└── fig/summary/plus1_vs_zero_and_zero_vs_minus1/
    └── bands_Theta_Alpha_Beta_Gamma_HFA/
        └── regions_dorsal_ventral/
            └── categories_.../
                ├── positive/
                │   └── merged_gain_loss_site_responses_positive_by_region.png
                └── negative/
                    └── merged_gain_loss_site_responses_negative_by_region.png
```

The final plot uses the complete pairwise source, including both `+1 vs 0` and
`0 vs -1`, to build the gain/loss response categories. The plotting wrapper
uses all configured bands and excludes outside
contacts by default. To disable only this final plot:

```yaml
output:
  final_barplot: false
```

or:

```powershell
python .\scripts\03_generate_response_plots.py `
    --input-output .\outputs\baseline_raw_YYYYMMDD `
    --no-final-barplot
```

To include outside contacts, set:

```yaml
intermediate:
  include_outside: true
```

Then rerun stage 3. Existing generated plots are not automatically deleted;
use the lower-level plotting script with `--clean` when old filtered exports
must be removed:

```powershell
python .\src\generate_gain_loss_figures.py `
    --output .\outputs\baseline_raw_YYYYMMDD `
    --plot-outside all `
    --clean
```

## 4. Run only selected stages

Edit `configs/run_all.yaml`:

```yaml
steps:
  intermediate: true
  comparisons: true
  response_plots: true
  lmm: false
  lmm_figures: false
  temporal_response_categories: false
  tfr_response_categories: false
  insula_csv: false

reuse_existing: true
overwrite: false
insula_band: HFA
```

Then run:

```powershell
python .\scripts\run_all.py `
    --config .\configs\run_all.yaml
```

Use `--input-output` to reuse an existing intermediate-data directory:

```powershell
python .\scripts\run_all.py `
    --config .\configs\run_all.yaml `
    --input-output .\outputs\baseline_raw_YYYYMMDD
```

Set `overwrite: true` or pass `--overwrite` when outputs must be regenerated.

## 5. Mixed-model configuration

Edit `configs/lmm.yaml`:

```yaml
model:
  preset: regional_patient
  p_adjust: fdr_bh
  fit_per_band: true
  fit_all_bands: false
```

Available model presets are `regional`, `regional_patient`,
`main_effects`, and `outcome_only`. Available p-value adjustments are
`fdr_bh`, `holm`, `bonferroni`, and `none`.

## Comparison behavior

The comparison stage creates these simple plot folders when their names are
present in `configs/comparisons.yaml`:

```text
fig/summary/minus1_vs_plus1/minus1_vs_plus1_by_band_and_region.png
fig/summary/plus1_vs_zero/plus1_vs_zero_by_band_and_region.png
fig/summary/minus1_vs_zero/minus1_vs_zero_by_band_and_region.png
```

The final gain/loss category barplot uses the `+1 vs 0` and `-1 vs 0` results
together:

```text
fig/summary/plus1_vs_zero_and_zero_vs_minus1/
```
